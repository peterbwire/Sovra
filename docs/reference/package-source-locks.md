# Local source locks

Status: **Partial G12; generation, verification and explicit locked CLI implemented
on Linux x86/x86_64/aarch64 with procfs.** This implements the approved
[G12 contract](../design/G12_MODULES_AND_LOCKS.md), without registry access,
version selection, downloads, build scripts or package-code execution by `lock`.

```text
svr lock PACKAGE_DIRECTORY
svr lock --check PACKAGE_DIRECTORY
svr check --executable-package --locked --format json PACKAGE_DIRECTORY
svr run --locked PACKAGE_DIRECTORY
svr build --locked --emit js PACKAGE_DIRECTORY
svr build --locked --emit exe --output OUTPUT PACKAGE_DIRECTORY
svr test --locked --format json PACKAGE_DIRECTORY
```

`lock` captures/parses the complete selected local graph and explicitly generates
`sovra.lock` at the requested root. It does not require semantic correctness.
`lock --check` only compares. Locked compilation still checks every selected body,
including private/unused functions, before execution or emission. Missing, stale,
malformed, unknown-version or over-budget locks fail without fallback, output
artifacts or automatic rewrites. A lock's presence alone does not enable enforcement:
unlocked commands retain their behavior. Formatting changes raw bytes and makes
an existing lock stale; regenerate explicitly after reviewing those changes.

Locked mode requires a package directory. `check --locked` additionally requires
`--executable-package` and refuses overlays, context-only, symbols and service-call
modes. Run arguments following `--` remain program arguments. Usage errors exit 2;
lock/compilation/publication failures exit 1. JSON executable checks retain the
existing report schema. Lock diagnostics use E4165; ordinary source diagnostics
retain their original codes and source ownership.

## Retained identity and schema

`load_package_sources` retains exactly the parsed UTF-8 manifest and source bytes.
`generate_source_lock(&inputs)` returns a read-only `SourceLock` with canonical
JSON; `verify_source_lock(&inputs, text)` compares the complete graph and hashes.
Neither writes. `check_source_lock(root)` reads and verifies the on-disk lock.
`compile_locked(root)` verifies and compiles the same owned inputs without source
or manifest rereads. `write_source_lock(root)` explicitly publishes a generated lock.

Version 1 has `format: "sovra-lock"`, integer `version: 1`, `root: "p0"`, and a
`packages` array. Package IDs follow first canonical-root discovery in deterministic
alias traversal, rather than display names or absolute paths. Each package retains:

- `id`, `name`, nullable `version`;
- `manifest: {sha256, bytes}` for the exact parsed manifest;
- `entry: {path, sha256, bytes}` and name-sorted `modules: [{name, source}]`;
- alias-sorted `dependencies: [{alias, path, target}]` using declared locator text.

Source paths are normalized package-relative slash paths. Package roots are not
serialized. Equal relative layouts produce byte-identical locks after relocation;
absolute dependency locators remain absolute and nonportable. Aliases/diamonds
retain every edge while sharing one canonical package identity. All digests are
SHA-256 of raw UTF-8 bytes, including comments and line endings. Object property
order and whitespace may differ on verification; unknown/missing fields, duplicate
decoded keys, wrong types, reordered graph arrays and forged identities/hashes fail.
Canonical generated JSON sorts object keys and ends with one LF.

The decoder rejects invalid Unicode escapes/surrogate pairs, raw controls,
trailing data and noninteger schema numbers. Limits: 8 MiB encoded input/output,
16 nesting levels, 16 KiB per decoded string, 8 MiB total decoded string bytes and
262,144 JSON nodes. Existing package/source/token/AST/interface/evidence/IR budgets
remain active; exhaustion returns no partially verified or compiled result.

## Publication and host limits

Publication anchors the canonical root through an opened directory descriptor,
stages bounded output with exclusive creation, verifies held staging bytes and
identity, and checks destination/parent conflicts before publication. Creation
uses no-clobber hard-link publication; replacement uses atomic rename. Existing
lock permissions/ownership must be preservable. Link, hard-link, special-mode,
read-only and unsupported-format targets are refused. Unchanged generated bytes
do not replace the file. Owned staging files are cleaned after failures; conflicting
external bytes are preserved in the tested prepublication conflict cases.

These checks do not lock out a hostile writer racing the final replacement,
provide an atomic snapshot of an entire changing directory graph, guarantee
power-loss directory durability, or preserve arbitrary ACLs/extended attributes.
A lock supplies reproducibility/integrity relative to reviewed expected bytes,
not publisher authentication or permission to execute untrusted code. Other hosts
fail guarded capture/publication explicitly; Linux evidence does not qualify
Windows, macOS, MSRV or release readiness.
